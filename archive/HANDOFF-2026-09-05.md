# Handoff — 2026-09-05: the Coldplate remap

The 09-04 session left one open item at the top of its list: *reprocess the
pre-cutover logs onto the corrected Coldplate curve*. That is done. Doing it
also corrected the account of what the fault was, and settled a caveat
`analysis/` had been carrying since it was written.

## What the fault actually was

The 218 was carrying **X186276**'s calibration curve on input 2. The Coldplate
is **X186279**. Both curve files were sitting on the cryostat machine, in
folders Jeff had already labelled "Wrong SN I Think" and "Correct SN"; they are
now in [`reference/sensor-curves/`](../reference/sensor-curves/).

They are not near-copies. X186276 is a CX-1050-**CU** unit and X186279 is a
CX-1050-**SD**, and X186276 is about 12% higher in resistance at every
temperature — the outlier among the four CX-1050 curves in that folder. So for
the resistance the Coldplate actually presented, the box named a temperature
that was too warm, everywhere, by 12–13% of absolute temperature.

The previous session wrote this up as "a transposed digit in the calibration
curve — a 6 where a 9 belonged", and concluded that a locally warped curve
could not be corrected without a measurement nobody had made. **The digit was
in the serial number.** What was loaded was another thermometer's calibration
in full, both files exist, and the correction is therefore exact arithmetic:

```
T_logged --[X186276.340]--> ohms --[X186279.340]--> T_true
```

That is the instrument's own linear interpolation between breakpoints, run
backwards and then forwards, so the round trip is exact rather than fitted.

| logged | true | | logged | true |
|---|---|---|---|---|
| 6 K | 4.93 K | | 77 K | 65.33 K |
| 10 K | 8.11 K | | 150 K | 130.42 K |
| 20 K | 16.22 K | | 300 K | 265.10 K |

## The independent check, which is the part worth trusting

Nothing above proves X186279 is the right curve — it is still, in the end, a
claim about which file belongs on which input. The data settles it.

A sample cannot rest colder than its own heat sink. Counting rows where
`Sample` < `Coldplate` across the three `analysis/` tables:

| | rows |
|---|---|
| as logged | **13,290** of 811,292, worst −30.19 K |
| remapped | **0** — in all three tables, at every power |

Not "fewer", not "mostly". Zero, and the zero-power settled rows now put the
sample **+0.29 K above** its sink (96 rows, min +0.21 K), which is an ordinary
small parasitic load. A wrong choice of target curve would not do that.

There is a second, cruder tell that pointed the same way before any of this:
at room temperature CD10's Coldplate sat at exactly **330.3200** for 905 rows,
which is the top breakpoint of X186276's table. The box was railed at room
temperature, on a cryostat whose other channels read 294–302 K.

## What landed

**`lschart/tools/recalibrate.py`** — generic, in `lschart` because remapping a
Lake Shore curve is not an LTSPM3 concern. Reads `.340` breakpoint tables,
composes two of them over a CSV column, `.gz` transparent both ways. Two
refusals are the substance of it:

- **It will not invert a railed reading.** Past the end of the loaded table the
  box clamped and the resistance is gone. Inverting the CD10 rail anyway yields
  292.6 K — indistinguishable from a plausible room temperature, and therefore
  the worst possible thing to write into a log. Those rows come out blank and
  are counted. 908 of them.
- **It will not write over its input.** A remap is a claim about which curve was
  loaded, and the old log is the only record of what the box actually said.

12 tests in `tests/test_recalibrate.py`, run against the two real curve files
rather than fixtures, including the round-trip identity and the correction
itself — so the docs and the curve files cannot drift apart silently.

**The data**, all of it in the gitignored `data/coldplate-recal/` with a README
carrying the commands:

|---|---|
| `cd10/` | 28 files, 298,617 rows. **What the viewer should open** for anything pre-cutover |
| `recorder/` | 16 logs, 08-24 → the archived 09-04. Five of them call input 2 `Cold Head` and were remapped under that name |
| `fit-inputs/` | the three `analysis/` tables |

**`reference/heater-calibration/` was remapped in place**, so `analysis/` reads
the corrected `T_c` with no argument and no code change. The as-logged tables
are in git history at `72c3f32`. Only the `Coldplate` column moved.

**Docs.** The "transposed digit / no correction can be quoted" story is gone

## What this changes downstream, and what it does not

`analysis/steps.py` re-run: **65 graded dwells, 17 with a usable τ** — the same
counts as before, because it grades on `Sample`, which never moved.

The **0.79 K anomaly is resolved**, and with it the reason `analysis/` declared
the model undefined below ~12 K. That restriction has *not* been lifted — it is
now unmotivated rather than disproven, and lifting it means re-deriving the
low-temperature end on the corrected `T_c`. `plot_gain.py` still shades the
region and its note now says why.

`fit_ode.py` was re-run on the corrected inputs; **check `analysis/ladder.csv`
and re-run the figures** (`plot_ode`, `plot_gain`, `pid_tuning`, `settling`)
before quoting any number from `analysis/README.md`'s "What came out" table,
which is still marked stale.

**Nothing in `control/` depends on any of it**, so none of this is a safety
matter and no default moved.

`LTSPM3_AUX_COUPLING["218.2"] = 0.0082` is **left alone**, but for a new
reason. Remapping `cd8_..._sample_monitor7.xls` scales the coldplate's
excursion by 0.84–0.88 depending on the window, so the honest value is about
0.0070. That is simulator scenery, the coherence logic only needs the coupling
non-zero and of the right order, and a 15% fidelity gain does not justify
perturbing a tested simulator. The old reason — "adjusting it would mean
inventing a correction" — is no longer true and has been removed from the docs.
